# Phase 1 可靠性（2026-10-25）

REL01–REL04：RecordsController 的业务写入统一经过 `_write`，事务完成后再读取快照。`writeCommitted` 表示本次操作是否提交；独立 `needsRecovery` 在提交后读取失败时保持到完整快照读取成功，`loaded=false`、`canWrite=false`。所有业务写入在仓储调用前检查可写状态；重读失败或尝试其他写入均不解除恢复锁。快照中的记录、所有心愿、当前选择及汇总恢复后才开放操作。首页沿用原读取提示；帮助及备份页在异常期间提供重读入口，计算器和心愿弹窗只能重读已提交操作。旧非金额编辑仅在已提交时进入只读恢复，未提交时保留输入并允许安全重试。

SavingRecord 分离普通输入与 `fromStorage` 校验；后者保留日历格式和其他领域不变量，但不依赖当前日期。仓储保存时再以注入时钟验证新日期，编辑只允许原样保留数据库中的既有日期。备份同属历史数据解码，设备日期不用于判定损坏；现有 `today` 命名参数保留调用兼容性。数据库版本仍为 4，无迁移、新依赖或资产修改。

## 数据与一致性

schema v2：saving_records 保留 v1 的 id、kind、description、baseline_minor、actual_minor、saved_minor、币种与时间，新增可空唯一 client_token。quick 类型允许空备注，只保存正数 saved_minor；旧三类继续兼容。所有金额用整数分；汇总在纯 Dart 中用 BigInt 检查 64 位溢出。

active_goal 为单行表（id=1），保存名称、目标整数分和 start_after_id。创建目标与读取 sqlite_sequence 在同一事务；边界采用 AUTOINCREMENT 的历史高水位，删除最大记录也不会复用它。编辑目标不写边界；编辑记录不写 id/创建时间/请求身份；可编辑发生日期不影响进度。

v1→v2 在 sqflite 升级事务内重建记录表，显式复制原始字段和 ID，恢复历史序列高水位，再创建空目标表。失败回滚，不自动删库。不凭空给旧用户生成目标或把历史总额灌进新目标。

写入成功后读取记录与目标的同一事务快照，再计算首页总额、目标进度和最近记录。计算/写入失败保留输入；写入已提交但快照失败时，弹窗只重试读取。新录入使用唯一 client_token，重复请求不重复新增。

Android 无业务网络权限；禁用系统备份/转移，未来显式导出仍需格式版本、恢复预览与事务验证。当前不承诺额外数据库加密。
