## 1. 目标、标杆与产品边界

### 1.1 我们要达到的体验

用户做出一个积极消费选择，几秒内记录；小猪用明确、有性格的动作回应；心愿向前推进；长期使用能感受到自己的积累与陪伴关系。用户可以立刻离开，也可以继续记录，不需要管理另一套游戏系统。

**核心体验句：我做了一个好选择 → 小猪认真接住 → 心愿有了真实变化 → 一起积累留下了可感知的痕迹。**

Duolingo 在本文中是角色一致性、反馈节奏、设计细节与持续打磨的质量标杆，不是页面、资产、机制或技术选型模板。不复制其品牌、角色、文案或素材；不宣称本文列出的机制等同于其完整实现。成熟度必须在 Wallehog 自己的使用场景中验证。

### 1.2 已确认、继续有效的约束

- GA-01：保留已认可首页结构、配色、字体、PS5 手柄与进度圆环核心构图。角色升级先在原位或短暂成功层完成，不借此重做首页。
- GA-02：核心路径始终是“加号 → 金额 → 确认”；不增加必填分类、预算、实际消费、备注或额外确认。
- GA-03：节省金额来自用户手工报告，不代表真实存款、账户余额或可花资金。画面金币只是成功隐喻，没有可消费的虚拟币余额。
- GA-04：数据库提交并读取一致快照成功之后，才可以发出成功反馈。动画不负责确认写入，也不决定金额、记录归属或成长。
- GA-05：不以消费或断签制造羞耻，不增加饥饿、健康、损失、倒计时压力、排行榜或强制每日任务。不按金额多少夸大人的价值。
- GA-06：Android、离线、SQLite；无账号、业务联网、遥测、广告、银行、支付或社交功能。用户不必打开通知，也能获得完整体验。
- GA-07：动效不拦截下一次操作，支持系统减少动态效果、读屏与生命周期中断。资产缺失时保留真实金额和静态反馈。
- GA-08：保留 Flutter/Dart/SQLite 基础。不引入 Unity/游戏引擎，不为未来设想提前添加运行依赖。

补充：本稿第 2 节记录的是 v1.8 历史基线；后续导航、心愿卡及计算器交互变化以 PRODUCT_SPEC.md 最新已批准条目为准，不能照本文历史基线回退界面。音效的必要性已确认，但本文仍是后续开发交接稿，不代表音频资产或播放功能已经接入。

### 1.3 本轮后续设计不包含

宠物经营、商城、抽奖、装饰收集系统、好友排行、云同步、签到奖励、付费机制、全新导航或目标档案页面。以后如确有需要，另行提出目标、成本与评审；不能作为本方案的默认组成部分。

## 3. 成熟度的验收定义

以下为后续阶段目标，均未因本文建立而自动达成。

| 层次 | 需要回答的问题 | 可评审的通过证据 |
| --- | --- | --- |
| M-A：动作可信 | 小猪是在接收金币，还是图片在上下移动？ | 静音、不读文字也能辨认注意、接收、开心和收尾；有部件动作与重心变化 |
| M-B：交互完整 | 重复操作、失败和中断时是否仍然自然？ | 快速连续记录、失败重试、切后台、退出、减少动画完整测试与录屏；金额始终正确 |
| M-C：成长有意义 | 一周后用户能说出积累带来了什么吗？ | 阶段差异样例、明确解锁规则、无压力文案；试用者能指出变化及其来源 |
| M-D：长期不烦 | 第一次喜欢的反馈，第几十次是否仍然舒服？ | 连续试用与重复播放评审，不为看完动画等待，不出现固定长演出或排队补播 |
| M-E：可交付 | 动画师交出的文件，开发能否直接接入？ | 资产清单、坐标/锚点、事件、状态、授权、性能记录、静态后备与验收用例齐全 |

最低可交付成熟 MVP 为 M-A、M-B、M-E 通过，M-C 有一个完整可感知阶段，M-D 有实际试用记录。不能仅凭动画数量、测试数量、代码合并或一次演示宣称“达到 Duolingo 成熟度”。

## 4. 游戏化结构：三种时间尺度

### 4.1 当下：每一次记录都被接住

GA-09：普通保存反馈必须是最常用、最精炼的一条。角色动作应有“注意到 → 接收 → 愉快回应 → 回到安静”四个可辨认阶段。金额大或小使用同等尊重的动作；不得按金额增加虚拟币个数、经验倍率或更盛大的常规演出。

### 4.2 中期：心愿有阶段，达成有记忆点

GA-10：以当前目标真实进度表达期待。保留已有 50%、100% 门槛，不额外添加 10%、25%、75%、90% 等高频门槛。过半动作比普通保存略有区别，达成动作更完整，但仍可立即离开。达成只表示自行报告的积累达到目标值，不暗示资金足够购买。

GA-11：达成之后保留该目标、真实金额及继续记录能力；不强制购买、不扣钱、不自动创建或清除目标。任何“开始新目标”入口只能复用已有自愿操作，不挤进确认流程。

### 4.3 长期：积累使小猪更熟悉你

GA-12（建议，待 D04 评审）：先复用现有五级次数门槛，不再建立经验、亲密度、能量等独立数值。每阶段至少有一个清楚但低调的角色动作/台词变化。新增动作是陪伴变化，不是等待领取的奖品。

建议阶段内容，不是已批准的新等级名称或素材需求：

| 现有有效次数 | 体验方向 | 可制作的差异样例 |
| --- | --- | --- |
| 0–4 | 从初见到被接住 | 基础接收、轻笑；首次单独一句欢迎 |
| 5–14 | 逐渐熟悉 | 接收后耳朵轻动，触摸时更自然地靠近 |
| 15–29 | 有共同节奏 | 增加一个短接收变体与对应本地台词 |
| 30–59 | 稳定陪伴 | 保留熟悉动作，偶尔使用更亲近的短回应 |
| 60+ | 长期陪伴 | 有完整收尾的成熟动作，不再用无限等级推动记录 |

动作变化不得要求记录更大金额；点击小猪不增加次数。删除记录时金额和等级继续真实重算，不能添加失落、掉落动画或“失去奖励”提示。阶段动作是否随当前等级回退，要随 D04 一起确认，不能悄悄改成永久经验。

## 5. 角色人格、语言与动作清单

### 5.1 小猪的人格

小猪是可靠、温柔、有一点俏皮的陪伴者。它认真接住用户的选择，但不评判用户的消费，不像客服反复播报，也不表现为需要照料的宠物。

| 场景 | 合适的表达 | 应避免的表达 |
| --- | --- | --- |
| 普通记录 | “收到啦，我们又靠近一点。” | “你终于忍住乱花钱了。” |
| 小金额 | “这一点，也算数。” | “才省这么点？” |
| 过半 | “回头看，已经走过一半啦。” | “只差一半，今天再冲一笔！” |
| 达成 | “这些小选择，真的积累起来了。” | “现在可以买了！” |
| 回来看看 | “见到你真好。” | “你已经好多天没来了，我很难过。” |
| 保存失败 | 明确错误与可恢复操作；角色保持中性 | 庆祝、责备或角色哭泣 |

GA-13：每个场景建议先制作 3–5 条短句，相邻不重复；选择依据为场景与有限变体，不做联网生成。正文最多两行作为标准字号下的目标，长文本和大字体允许扩展，不截断重要状态。读屏只宣告一次成功与核心里程碑，不逐帧播报金额。

### 5.2 最小动作库

以下为制作交接清单；优先完成 P0，P1/P2 不应阻塞核心验证。

| 资产 ID | 优先级 | 触发 | 表演重点 | 默认结束姿态 |
| --- | --- | --- | --- | --- |
| pig_rest | P0 | 静态首页、动画后备 | 安静、清晰、与现图一致 | 中性主姿态 |
| pig_receive_a | P0 | 普通成功 | 眼神注意投币口、接收时短压缩、耳朵延迟回弹、笑意 | 主姿态 |
| pig_first | P0 | 首次事件 | 轻微惊喜与确认，不长时间演出 | 主姿态 |
| pig_halfway | P0 | 50% 跨越 | 自豪地抬头或点头，区别于整体缩放 | 主姿态 |
| pig_complete | P0 | 100% 跨越 | 明确开心、一次完整短庆祝，有收尾 | 主姿态 |
| pig_pat | P0 | 点击顶部小猪 | 对触摸方向有所回应；不增加经验 | 主姿态 |
| pig_receive_b | P1 | 普通成功变体 | 同一人格和节奏，表情或耳朵有差异 | 主姿态 |
| pig_level_up | P1 | 原成长事件 | 熟悉程度的变化；不叠加第二场演出 | 对应阶段主姿态 |
| pig_greet | P2 | 自愿回访提示 | 轻欢迎、不催促 | 主姿态 |
| pig_blink | P2 | 另行评审 | 如需待机，先验证分心与耗电 | 主姿态 |

当前规则没有循环待机。不得把 pig_blink 的清单条目理解为已授权持续眨眼、呼吸或漂浮。P0 的变形发生在局部部件与重心，不是只将整张图片缩放、旋转。

## 6. 动作分镜与时间编排

### 6.1 时间基准

GA-14：以“提交与一致快照读取已成功，计算器关闭后画面可见”为演出时间 t=0。存储耗时不包含在动画预算里；写入中使用真实的保存状态，不提前播接收成功。不能为了等动画完成而延迟数据库提交或冻结操作。

以下时间是打磨初值，待 D05 真机验证；不替换当前已运行的 900ms 规则，除非对应里程碑实施时获批。

| 相对时间 | 角色/金币 | 数据/界面 | 实施注意 |
| --- | --- | --- | --- |
| t=0–120ms | 小猪注意到，金币淡入 | 首页已持有真实快照，计算器关闭 | 防止演出最重要部分藏在退场弹层后 |
| t=120–500ms | 金币沿弧线飞向投币口，小猪有期待姿态 | 累计金额和 Goal 使用同一反馈节奏平滑接近真实结果 | 不按动画帧写金额或重新算账 |
| t≈500–550ms | 金币缩窄并被投币口遮挡；接收姿态切换 | 数值可在入槽附近完成收敛 | coin_impact 只触发视觉/可选触觉 |
| t=550–900ms | 身体短压缩、抬起、耳朵跟随、自然收尾 | 鼓励语显现；读屏一次性宣告成功 | 禁止在最后一帧突然回到不同姿势 |
| t=900–2300ms | 主姿态，文字短暂保留 | 用户可继续操作 | 普通反馈沿用短展示窗口 |
| 里程碑额外空间 | 如需延长，建议表演总长不超过 1400ms、文字层不超过 2800ms | 仍可立即 Add 或离开 | 值为建议，不能默认延长所有保存 |

真实金额必须在中断、减少动画或回到页面时直接正确呈现；不能因动画未走到入槽点而保留旧值。首次打开或恢复页面不从零补播历史金额。

### 6.2 画面与空间

GA-15：顶部小猪保留现有尺寸和位置。精细投币优先在原有局部成功层中放大表演；主体、投币口、金币、阴影、文字的锚点由同一局部坐标系管理。不要硬编码整屏坐标追逐顶部图像，也不要同时播放两个彼此独立的主角动作。

金币应从外部进入投币口，并通过前后遮挡或明确缩窄表现“进入”；不能停在头顶后突然消失。小猪脚下阴影随离地高度变化，但不出现长时间闪烁或常驻粒子。角色身体、眼神与金币路径的方向必须一致。

GA-16：触摸反馈不需要金币，也不更改金额。连续点猪不排队，播一次后允许取消/重启短动作；保存成功优先于触摸。角色反馈层必须可穿透点击，按钮不因演出临时消失。

### 6.3 音效是核心反馈的一部分（用户已确认）

GA-23：成功体验按“画面 + 声音 + 角色动作”共同设计。金币进投币口时，应有轻、短、清楚的入槽声音，让用户感到“这笔记录被接住了”。它是反馈的一部分，不是做完动画之后随意附加的提示音。音效不依赖是否采用 Rive；角色资产与音频播放可分别选型，再由同一展示计划同步。

声音风格：柔和、圆润、有轻微实体质感，接近小金币进入小猪存钱罐的短促碰撞与温暖收尾。避免尖锐报警、高音量现金收银、赌场老虎机、持续铃声和夸张金币雨。不按节省金额增大音量或提高奖励强度；不引入背景音乐、语音朗读或持续动物叫声。小猪叫声是否需要、是否符合角色，另行评审，不是本次默认要求。

#### 6.3.1 最小音效清单

以下片段时长为制作起点，未测量前不作为已达到的指标。普通操作先保证一声入槽舒服，不追求每个按钮都响。

| 音效 ID | 优先级 | 对应事件/时刻 | 听感与建议时长 | 播放约束 |
| --- | --- | --- | --- | --- |
| sfx_coin_deposit | P0 | 真实成功后的 coin_impact | 轻微金属碰撞 + 柔和容器共鸣，约 120–300ms | 每个有效事件最多一次，不在点击保存时提前响 |
| sfx_first_tail | P0 | 首次接收后的短收尾 | 温暖、简单的两音或短亮音，约 200–450ms | 与入槽作为一组编排，不能再叠一组普通奖励 |
| sfx_halfway_tail | P0 | 过半回应的关键动作 | 比普通稍明亮，约 250–600ms | 只播本次主里程碑的收尾，不再叠升级音 |
| sfx_complete_tail | P0 | 达成短庆祝的关键动作 | 完整但克制的短乐句，约 500–900ms | 整组建议不超过 1200ms，可随退出停止 |
| sfx_pat | P1 | 点击小猪且短回应确实开始 | 柔软触碰/轻弹，约 60–180ms | 快速点击不叠音，不能变成长鸣 |
| sfx_level_tail | P1 | 升级被选为主回应时 | 与同一声音家族一致，约 250–600ms | 不与达成或过半收尾同时播 |
| sfx_ui_press | 暂不加入 | 加号、数字键等 | 暂无制作要求 | 先用视觉按压；避免每次输入产生噪音 |
| sfx_error | 暂不加入 | 保存失败 | 保留明确文字错误 | 不播庆祝，也不增加责备式失败音 |

制作可以把入槽和对应收尾导出为组合片段，也可以按时间标记分片播放；必须在样机中比较同步与取消成本。组合片段仍要能被关闭/退出停止。不要为每个等级制作一套无区别的文件。

#### 6.3.2 同步与调度

GA-24：音效与视觉共用 eventId 和展示时间轴。只有提交与一致快照成功后才创建计划；sfx_coin_deposit 锚定真实可见的 coin_impact，不能通过保存按钮点击或另一个固定延时独立触发。解码资源可提前准备，声音必须等到有效事件与时间标记才播放。

建议入槽画面与声音的起始偏差目标不超过 50ms，冷启动与暖机分别测量；这是待真机验证的目标，不是当前保证。若资源太晚就绪、视觉已结束，应跳过声音，不能几秒后补一声。音频加载失败不延迟或撤销保存，立即无声降级。

GA-25：同一时刻只允许一组角色反馈音效，入槽与收尾属于同组；目标达成、首次、过半、升级按批准的主回应选择，不把全部候选混播。快速连续保存不积累播放队列；旧组停止或短淡出后，新组按自己的入槽时刻播放。持续时间相同也不能简单全局节流到误吞下一笔的成功文字与视觉。

用户再 Add、切目标、离开首页、切后台或关闭音效时，取消当前组与未触发的音频回调。重新打开应用、页面重建、编辑、删除、导入和窗口变化不补播历史声音。音频播放完成回调不得写入记录或判定保存成功。

#### 6.3.3 开关、系统声音与可访问性

GA-26：应用必须提供一个容易找到的“音效”开关，持久化到本地轻量设置；关闭立即生效并停止当前声音，重启仍保持关闭。入口复用现有设置/帮助区域，不能为此新增首页卡片或改变核心录入路径。设置存储与备份是否包含该偏好需在实施时明确；不得为了一个开关新增数据库迁移框架。

D09 决定首次安装默认开启或关闭，以及现有安装升级时如何初始化。音效必要性不等于默认必须有声，不在未确认时擅自启用现有用户设备声音。

不得主动调高系统音量、改变用户静音/免打扰设置，或以强行取得音频焦点打断音乐、通话或读屏。媒体音量为零必须无声。铃声静音、振动、免打扰与媒体音量是不同情形，不能假定媒体播放天然遵守所有静音策略；需要按 D09 定义策略并在 Android 真机分别验证。无法可靠确定安全播放条件时优先无声，不申请侵入性的系统控制权限来绕开限制。

GA-27：减少动态效果和关闭音效是两种独立偏好；不能因为跳过动画就失去保存确认，也不能自动把减少动画理解成同意播放声音。减少动画时若用户开启音效且系统策略允许，可在静态成功呈现时播放一声短入槽音，不再安排动画里程碑长收尾；实现前纳入 D09 确认。TalkBack 下优先保证成功宣告清楚，不用音效覆盖读屏。关闭声音或听力受限时，仍能从静态画面和语义获知同样结果。

#### 6.3.4 音频资产与开发交接

GA-28：音效制作交付可编辑源工程、无损母带及经目标设备验证的运行时文件，并注明素材授权与商业分发范围。格式/采样率/声道由 D10 样机决定，不提前锁定插件或编码；短音效应评估预加载、解码时延与资源释放，不假设一个压缩文件在所有播放后端表现相同。

每个片段的交接表至少包含：clipId、assetVersion、文件/校验值、时长、采样率、声道、峰值/响度测量方法及结果、相对增益、起止静音长度、对应视觉标记、允许的重叠/中断方式、静音后备行为与授权来源。不要只交一个未标音量的音频文件。短促音效除响度数值外，还须做听感评审，避免整合后过响、削波、爆音或头尾截断。

同组金币、角色与里程碑音效应来自一致的声音设计，近距离手机外放和耳机分别试听；不能直接用未经授权的其他产品声音。AI 生成或素材库下载的片段也要记录来源、许可与编辑处理，不因来源不同免除检查。

### 6.4 触觉仍为可选待评审

D06 中音效必要性已获用户确认，触觉仍未批准。若后续启用，触觉最多在真实成功的入槽点短触发一次，遵守系统设置、可关闭；取消或重建不重播。不得把本次对音效的确认扩展为触觉、背景音乐或动物语音全部获批。

## 7. 事件、优先级与中断契约

### 7.1 领域事实与展示事件分开

GA-17：后续建议把 HomePage 中分散的反馈判断收敛为“纯 Dart 规则 → 展示计划 → Flutter 播放器”，沿用轻量分层，不为此引入框架。

| 层 | 负责 | 禁止 |
| --- | --- | --- |
| domain | 已保存记录、前后 Goal 进度、有效次数、事件候选 | 读取 Widget、计时器、触觉或动画控制器 |
| application | 写入/读取结果、操作身份、前后快照与新增事实 | 由动画回调完成存储事务 |
| data | 记录与归属；若获批则保存展示去重状态 | 因资产丢失删库或改变汇总 |
| presentation | 选一条主回应、调度、取消、降级、可访问性 | 发经验、改金额或创建记录 |
| assets/runtime | 播放动作，提供可选时间标记 | 发业务请求或自动解锁成长 |

建议事件接口，字段仅作为后续实现契约草案，不表示已有公共 API：

```json
{
  "eventId": "本次逻辑操作的稳定身份，重试不变",
  "origin": "newRecord",
  "recordId": 42,
  "goalId": 3,
  "deltaMinor": 2300,
  "beforeGoalMinor": 2700,
  "afterGoalMinor": 5000,
  "targetMinor": 10000,
  "beforeChoices": 4,
  "afterChoices": 5,
  "snapshotRevision": "同一读快照的本地版本身份"
}
```

只有提交和快照均成功、来源为真实新增、稳定身份未被本次播放器处理的事件进入成功通道。编辑、删除、导入、启动、窗口变化均是状态更新，不冒充 newRecord。前后比较必须为同一个 Goal；无 Goal 仍可普通成功。事件与错误消息分开，错误消息不得被成功层覆盖。

### 7.2 一个操作，只安排一个主演出

GA-18（建议，待 D03）：主演出优先级为目标达成 > 首次记录 > 过半 > 升级 > 普通。当前 J02 的顺序是达成 > 过半 > 首次 > 普通，且升级作为独立字段叠加；不能直接把建议顺序写进代码。

如一笔同时过半与升级，主动作展示一个，成长状态照常正确更新，副信息可用同一气泡中的一行文字表达。不要排队播“过半→升级→首次”三场庆祝；欢迎回来不覆盖成功里程碑，也不另弹第二层。

### 7.3 中断矩阵

| 情况 | 建议行为 | 数据要求 |
| --- | --- | --- |
| 保存写入失败 | 保留输入，显示可重试错误，不发成功事件 | 不产生记录 |
| 已提交但读取失败 | 明确已保存，沿用只重读的重试；成功读取后最多一条反馈 | 不重新插入 |
| 再次点击 Add | 立即收起旧层，取消旧时间标记/音效/触觉，打开输入 | 上一笔保存不撤销 |
| 成功层期间切 Goal | 取消旧 Goal 专属演出；旧消息不能贴在新 Goal 上 | 各自进度正确，原记录归属不变 |
| 快速连续保存 | 新事件替换旧演出，不形成队列、不补播被中断事件 | 每次明确确认各存一次，重试请求仍幂等 |
| 触摸期间保存成功 | 成功覆盖触摸，平滑接回主姿态 | 触摸不增加次数 |
| 离开首页/应用切后台 | 停止解码、定时器和动效，不在后台播放音效或触觉；回来直接静态正确且不补播声音 | 不重播旧事件 |
| 页面重建/旋转/缩放 | 保留或取消当前展示计划，禁止重新生成成功事件 | 当前心愿与记录不变 |
| 资产损坏、运行时加载失败 | 静态猪、成功文字与真实金额降级，记录非阻塞诊断 | 已保存不能显示为“保存失败” |
| 系统减少动画中途开启 | 取消移动/缩放/粒子，立即收敛静态状态 | 不取消保存，不隐藏成功事实 |
| 进程在提交后被终止 | 重开后显示真实快照；不承诺恢复未看到的庆祝 | 不重复记录，不因缺少动画状态破坏数据库 |

GA-19：播放器回调必须检查事件身份、mounted/生命周期、当前页面及是否仍是有效计划。异步加载旧资源返回后，不得复活已取消的演出。

## 8. 去重、首次与成长：规则边界

### 8.1 当前规则必须准确继承

- 首次当前依据新记录 ID=1；不是“当前只剩一条记录”，也不是“导入之后第一次打开”。
- 50%/100% 为同一 Goal 保存前后跨越，以整数分判断。当前允许删除回退后，未来新增再次跨越时再回应。
- 升级根据当前有效 Good Choices 次数推导，新增仅增加一次时才判断跨级。已有 SQLite pig_celebrations 按等级原子去重，和实际等级分开。
- 现有升级标记在演出前领取；领取成功后进程退出/用户立即操作，可能没有完整看到庆祝。它是防重复的展示记录，不是“用户确实看过”的证明。
- JSON 备份不等于所有展示标记的跨设备同步。不得承诺恢复后仍永久记得每场演出。

### 8.2 待评审的稳定策略

D02/D03/D04 获批前不建新表。若以后要求“每个心愿每个门槛终生只庆祝一次”，需定义键、作用域、删除/重新创建、目标金额编辑、备份与迁移语义；建议键包含稳定 goalId、milestoneKind、ruleVersion，避免复用名称。

不能把“准确播放且只播放一次”作为没有条件的承诺：动画播放与 SQLite 事务无法原子完成。建议选择“最多尝试一次，允许因主动中断或进程退出而没看完”；不为了补播打断下一次使用。若选择可恢复投递，须额外设计 pending/consumed 状态、有效期限和恢复时机，再评审复杂度。

如替换 ID=1 的首次判定，必须先定义“本地安装第一次”“第一笔有效金额记录”“导入之后首次”等差别，考虑旧非金额记录、迁移、高水位与整体恢复；不能改成简单的 records.length==1。

## 9. 技术路线与素材交接

### 9.1 先做一个完整动作样机，再选路线

Flutter/Dart/SQLite 继续作为基础。Flutter 负责页面、输入、数据展示及播放调度；角色动作素材是需要补充的能力。具体运行时与依赖未定。

| 路线 | 适用情况 | 主要成本/风险 | 必须先验证 |
| --- | --- | --- | --- |
| 保留立体画风，预渲染透明帧/图集 | 动作数量有限，要求接近现有小猪外观 | 解码内存、纹理尺寸、文件体积、动作衔接 | Android 透明边缘、帧缓存、包体、首帧、重复播放内存 |
| 分层角色 + Flutter 原生变换/绘制 | 简单部件表情，团队能维护分层资产 | 绑定与遮挡靠代码，复杂表演制作成本高 | 部件对位、眨眼/嘴型可读性、维护难度 |
| Rive 等二维交互角色运行时 | 需要细部表情、可控动作混合 | 需重制适配资产，评估依赖、导出授权和目标设备兼容 | 可接受的画风样机、Flutter 集成、内存与授权 |
| 真正实时三维 | 本产品当前没有必须支持的场景 | 模型、材质、灯光和运行时成本 | 本方案不进入；需求变化时另评审 |

倾向先验证第一条以保留已认可画风，但不是已批准选型。预渲染动作仍需要制作源资产；不能从单张现有 PNG 自动获得可靠的完整表情与背面结构。Rive 也不能把 PNG 导入后自动变成成熟角色。

同一角色动作在 56dp 首页尺寸与约 104dp 成功层尺寸下分别检查。不要把视频/GIF 直接作为最终格式结论，也不要假设某种透明编码在所有 Android 解码路径上可用。格式在 D01 样机结果中确认。

### 9.2 动画交付包必须包含

| 交付项 | 内容 |
| --- | --- |
| 可编辑源文件 | 对应软件/版本、模型或分层源文件、材质/贴图/绑定；保存可继续修改的版本 |
| 音效包 | 无损母带、运行时文件、源工程、时长/响度/增益、视觉事件映射、静音/取消约定与授权，见第 6.3 节 |
| 运行时导出 | 每个动作的文件、命名、格式、实际像素尺寸、帧数、帧率、时长、校验值 |

| 静态后备 | 与主姿态一致的透明图片，减少动画与加载失败可直接使用 |
| 锚点与裁切 | 整体边界、脚底、投币口、金币终点、阴影中心、遮挡层；统一归一化坐标 |

| 视觉规则 | 镜头角度、灯光、阴影、尺寸、透明边缘、色彩；与原素材并排对照 |
| 变体映射 | 哪些可共用，哪些是成长差异；无资产阶段使用哪个后备 |
| 预览与演示 | 无声预览、正常/减少动画录屏、两种显示尺寸、浅/深背景边缘检查 |
| 授权与来源 | 原创过程、第三方模型/字体/纹理许可、可分发权、工具限制，不复用未授权参考图 |

  fallback.png

## 10. 性能、可访问性与离线降级

### 10.1 性能目标草案（D07）

以下为工程初值，样机测量后批准；没有测量前不得标为通过。

| 指标 | 建议初值 | 记录方式 |
| --- | --- | --- |
| 普通保存演出 | 900ms 左右完成主要动作；文字短暂保留 | 录屏帧时间与事件时间对照 |
| 演出可见后的首个回应 | 100ms 内有可辨认变化；资产未就绪立即静态后备 | 区分存储、弹层关闭、资源加载和首帧时间 |
| 60Hz 帧预算 | UI 与 raster 各按约 16.7ms 检查；暖机重复播放目标超预算帧 <1% | 真机 profile 分别统计两个线程；报告样本数、p95/p99和尖峰，不只看平均值 |
| 角色资源增加包体 | 建议增量 ≤8MiB | 同构建方式比较普通 release APK；超限须说明 |
| 动画带来的峰值内存增量 | 建议 ≤32MiB | 同一页面静态基线与播放峰值比较，含解码缓存 |
| 重复操作 | 连续 50 次播放/中断后内存趋稳 | 记录预热后的基线、峰值与最终值，检查控制器和图像释放 |
| 待机与后台 | 无循环解码、角色定时器或持续重绘 | 后台与静态首页检查 |

估算示例：一帧 512×512 RGBA 未压缩约 1MiB；24 帧全部常驻已约 24MiB，还没计入其他纹理与运行时开销。文件压缩得很小不等于运行内存小。先做按需加载和有界缓存，不提前把所有阶段、所有动作全部解码。

当前平板手机视口验证不能替代独立手机的性能验收。正式确认资源方案前至少选一台目标范围内的较低性能 Android 手机，记录型号、Android、刷新率、构建模式、温度/负载及测试条件；未具备设备时明确标为未验证。

### 10.2 可访问性

GA-21：系统减少动态效果时，金币飞行、跳跃、形变、摇摆、粒子和自动转场演出均跳过；保留静态猪、成功状态和里程碑文字，数值立即真实。中途开关也要有效，不能只在组件首次创建时读取一次。

GA-22：读屏顺序为保存结果→金额→关键里程碑；角色装饰与金币不重复获得焦点。按钮语义、焦点返回、至少可用的触碰区域、大字体换行在现有手机和平板布局中验证。不用闪烁、颜色差异或声音单独传达完成与失败。

离线所有必要素材随包提供。加载失败仅影响表现；不要联网补图。静态后备也缺失时仍显示清楚的保存文字与金额。

## 11. 验收用例与交付证据

每个阶段交付都给出“需求编号 → 规则/资产 → 测试或录屏 → 限制”对应关系。下列为后续必须覆盖的矩阵，不表示现有 156 项已经覆盖全部组合。

| 用例 | 预期 |
| --- | --- |
| 普通金额、无 Goal | 成功投币一次、金额真实，不伪造心愿或奖励 |
| 首次记录与跨目标门槛同笔发生 | 按批准优先级一个主动作，无多弹窗 |
| 目标 101 分，从 50 到 51 分 | 此时才跨过一半，不被显示百分比提前触发 |
| 已完成目标继续记录 | 总额继续增加，进度展示封顶，无反复完成演出 |
| 编辑、删除、恢复、重启与旋转 | 数据重算，无新增成功事件 |
| 切换心愿后保存、保存期间旋转 | 唯一归属正确，旧 Goal 演出不贴到新卡片 |
| 提交成功后读取失败，再重读 | 一条数据库记录；明确状态，成功演出最多一次 |
| 连续保存、重复确认、成功期间再 Add | 无重复写、无动画排队、可立即输入 |
| 入币前/后退出、切后台、返回 | 不崩溃、不后台触觉、不补播历史演出 |
| 损坏、缺失、过慢的资产 | 静态后备可用，不阻塞保存或误报写入失败 |
| 减少动画在播放前/中开启 | 不播放/立即停止动态，保留静态成功 |
| 小额/大额、长中文/大字体、360/390dp | 同等尊重、文字清楚、按钮可达、无溢出 |
| 原生手机、平板与恢复参数 | 手机先验收；临时分辨率/密度/旋转值有原值与恢复证据 |
| TalkBack 与静音 | 一次成功宣告、无装饰抢焦点；无声仍可辨认 |
| 50 次播放与取消、冷启动首帧 | profile 数据与生命周期检查达到批准预算 |

必须提供的证据：

1. 连续真实 Android 录屏：Add、逐键输入、保存、角色注意与接收、金额与 Goal 更新、再 Add；注明普通或测试包、样本数据和手机视口来源。
2. 首次、50%、100%、升级冲突、失败重试、减少动画、中断各至少一个可核对样例；成功动画不能用静态截图替代验收。
3. 角色大小对照、投币口关键帧、静态后备与故障降级截图；资产源文件与授权清单。
4. 规则/控制器/迁移/Widget/必要真机测试结果，format/analyze/构建日志。涉及展示状态迁移则补升级、回滚、备份往返用例。
5. 真机 profile 性能记录。debug 集成测试录屏可证明流程，不能单独证明 release 性能。
7. GA-29：必须提供包含实际应用音轨的 Android 连续录屏，核对声音与金币入槽同步；不能将无声音的 adb screenrecord 文件标为音效验收。设备不支持应用内录时，可用明确注明的外部录制检查听感，另用事件时间戳测量同步；不在事后给静音录屏配音冒充实际运行。保留无声/音效关闭、媒体音量零、铃声静音、免打扰、读屏、耳机/外放、快速连存、切后台与加载失败证据。
6. 开发完成且验证后，普通包 adb install -r 覆盖升级、保留记录与设置、启动确认；测试包不能替代日常交付。设备未连接/确认未完成时如实记录。

## 12. 试用：怎样判断长期体验真的变好

遵守无遥测边界，通过开发期自愿试用、人工观察与访谈，不新增埋点、后台上传或为了数字要求用户多记钱。涉及录屏时只用同意提供的数据或独立测试数据。

建议 5–8 位试用者、7–14 天；这是方向性发现，不是统计显著性或留存证明，也不是已批准的招募任务。首次观察与一周后分别询问：

- 不读说明，能否知道保存成功、小猪收到、当前心愿变化？
- 第十次左右是否觉得动画重复、吵或挡操作？有没有为了避开动画或声音少用一次？音效是否刺耳、突然过响、打断音乐，关闭后是否仍舒服？
- 能否说出角色的性格，以及一项实际可见的阶段变化？
- 是否误以为金币是可花余额、等级奖励消费克制、目标完成就可以买东西？
- 有没有因为等级而拆单、乱记或产生记录压力？出现这种反馈时优先调整成长表达，不能将“更多记录”直接视为成功。
- 减少动画用户是否获得同等清楚的结果与尊重？

记录每条问题、出现条件、设计解释和改进证据。具体达标标准由试用计划确认；不能凭少量好评宣称留存提升。允许结论是“某个演出需要缩短或删除”。
