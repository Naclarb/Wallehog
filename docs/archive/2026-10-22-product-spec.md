## 已确定需求与验收

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| R01 | 手工选择性记录 | 无账号即可离线录入；不要求完整消费流水 |
| R02 | 独立指标 | 首页分别展示已节省金额、好选择；金额旁有非实际存款说明 |
| R03 | 可量化节省 | 低于既定预算、选择便宜替代品可增加金额；计算资格细节见 D02 |
| R04 | 放弃可选购买 | 计入好选择，不自动计金额；不根据商品原价直接生成节省 |
| R05 | 可纠正 | 历史支持编辑、删除；操作后首页与心愿汇总一致，重启后仍一致 |
| R06 | 猪成长 | 依据好选择，不能由金额驱动；首个里程碑使用静态占位 |
| R07 | 心愿 | MVP 一个目标；有明显进度及“激励进度，不代表可用资金”说明 |
| R08 | 安全表达式 | 支持 +、-、*、/、括号；无 eval；错误可理解且不写入数据 |
| R09 | 本地持久化 | SQLite，Android 优先；无网络、账号、遥测、广告或金融集成 |
| R10 | 温和反馈 | 无断签惩罚、消费羞辱或任意预算比例门槛 |
| R11 | 清晰空状态 | 无记录、无心愿时分别说明并提供相应入口，不伪造数据 |
| R12 | 可验证业务规则 | 计算、舍入、汇总、编辑与删除有自动化测试 |
| R13 | 可扩展性 | 动画与领域独立；本地备份/导出有规划，不在首轮实现 |

## MVP 用户流程

首页 → “记录一个好选择” → 选择决策类型 → 填入该类型需要的比较依据与金额表达式 → 查看结果和说明 → 保存 → 首页更新。

首页 → “选择记录” → 记录详情 → 编辑或删除 → 所有相关汇总刷新。这里是积极决定的历史，不是支出流水；首页不展示参考图中的交易列表。

首页 → 设置一个心愿 → 查看激励进度。目标计算基准尚待 D05 确认。

## 建议决策与未决问题（单独评审）

| 编号 | 待决定事项 | 建议 | 影响 / 需要用户确认 |
| --- | --- | --- | --- |
| D01 | 货币与精度 | MVP 单一人民币 CNY，以分存储；不支持换汇 | 是否需要其他货币？后续换币不能直接重新解释旧数值 |
| D02 | 资格与差额 | 预算内支出、便宜替代：基准应在决定前成立且 > 实际支出 ≥ 0；每条有效记录计 1 次好选择。零差额/超出基准不作为这两类有效记录 | 是否接受？是否存在其他零金额好选择类型？ |
| D03 | 放弃购买输入 | 仅要求决策描述，可选备注；金额固定 0，不提供原价折算入口 | 是否允许其他“只计次数”类型？ |
| D04 | 计算与舍入 | 十进制输入支持小数和一元正负号；先用精确有理数计算每个金额字段，最终按分四舍五入（中点远离零），再算两个整数差额；拒绝负金额 | 舍入时机与规则会影响 1 分差异，必须确认 |
| D05 | 心愿进度基准 | 全部有效已节省金额 / 当前目标金额；显示进度最大 100%，实际累计值不截断；无扣款、无占用、无消费资格含义 | 还是仅累计设置目标之后的金额？切换目标是否重算？ |
| D06 | 目标管理 | 一次一个，可改名、改金额或清除；目标 > 0；达标仅庆祝、不自动扣减金额或创建新目标 | 是否需要“完成/归档”状态？MVP 建议不做 |
| D07 | 猪成长与删除 | 首轮仅静态猪；后续根据当前有效好选择重算成长，编辑/删除不播放负面反馈 | 成长档位、外观以及是否允许阶段回退待后续评审 |
| D08 | 日期和重复 | 保存创建时间、修改时间；允许用户选择发生日期，不允许未来日期；不自动去重，每条计一次 | 是否需要补记日期？同一决定是否允许多条？ |
| D09 | 输入保护 | 表达式最多 128 字符、32 层括号；仅 ASCII 数字与运算符、空格、小数点；拒绝科学计数法、逗号、函数；单字段最多 999,999,999 分 | 上限与兼容输入方式待确认，汇总另做整数溢出检查 |
| D10 | 删除体验 | 删除前确认；成功后重新读取汇总；不做回收站 | 是否需要撤销？影响备份恢复与数据模型 |
| D11 | 对外发布 | 专用 Wallehog Git 仓库，公开前确定许可证、包名与中英文入口 | 当前仅发现父级本地仓库，无 remote；需目标仓库地址 |

## 计算验收样例（采用建议规则后才生效）

- 基准 30 元、实际表达式 `10 + 5`：节省 1500 分，好选择 +1。
- 便宜替代基准 20 元、实际 12 元：节省 800 分，好选择 +1。
- 放弃一件标价 300 元的可选商品：节省 0，好选择 +1。
- 上述三条合计 2300 分、3 次；第一条改为实际 20 元后变为 1800 分、3 次；再删第二条后为 1000 分、2 次。
- `2 + 3 * 4` = 14；`(2 + 3) * 4` = 20；`1 / 0`、括号不配对、未知字符与超限输入均报错，不保存。
- 建议 D04 下 `0.1 + 0.2` 精确得到 30 分，`1 / 3` 得 33 分，`0.005` 得 1 分；不允许重复浮点累计。
- 保存失败时保留表单、解释重试；数据库写入失败不提前更新成功状态。
